## S8.2 self-review of `git diff main...linux-support` (for Claude's second review)
Changed src: `runner.ts` (resolveClineEntry Linux discovery S2.2, launch `node <entry>` S2.4, hub-stop fallback S4.2), `procs.ts` (S3.2/S3.4), `verify.ts` (S5.2), `rules.ts` (S6.2), `snapshot.ts` (S7.2/S7.4). Plus tests, `scripts/` (check-locked, linux-check, linux-smoke) and the workflow.
- **Windows branches.** `resolveClineEntry`: win32 still returns `%APPDATA%\npm\node_modules\cline\bin\cline` (now via `path.win32.join`, same result on Windows). One intended change on every OS (plan S2.2 step 2): a non-empty `CLINE_MCP_CLINE_ENTRY` env var now overrides discovery, including on Windows. Launch: `executable = windowsEntry ? execPath : "cline"` and `spawnArgs = windowsEntry ? [entry, ...args] : args`; on win32 a missing entry already throws `launch_failed` before this point, so the Windows spawn is unchanged. `procs.ts`: the Windows PowerShell code is byte-identical (only the signature gained a 3rd optional parameter). `verify.ts`: the change is inside the POSIX branch only. `rules.ts`: the Windows string is unchanged. `stopDedicatedHub`: the win32 path is the same; Linux now also runs the scan. `snapshot.ts`: the check-ignore filter runs on all OSes; on Windows it only drops paths under a junction, which restore refuses as links anyway (CI windows 600 pass / 0 fail).
- **No new shell use.** No new `spawn`/`exec`/`shell: true`. `/proc` is read with `fs.promises` only; `resolveClineEntry` uses `existsSync`/`realpathSync`.
- **`/proc` parsing vs races.** readdir failure → `undefined` (unknown, so Gate 6 stays unconfirmed). A process that exits between readdir and the reads → ENOENT → skipped. Empty cmdline (zombie/kernel thread) → skipped. The whole scan is bounded by `min(PROCESS_TABLE_TIMEOUT_MS, timeoutMs)` and the abort signal (a real Promise race; S3.4 attempt 1 was rejected for not having one). Residual risk: PID reuse between reading `cmdline` and `status`, or between listing and `killTreeAndWait`, could hit a new process with the same PID; the window is small and the same exists on Windows.
- **Never touching other users' processes.** Each candidate's `status` real UID must equal `process.getuid()`; if `status` can't be read the process is skipped. `selfPid` is excluded. The kill list is narrowed further by `hubDaemonPidsOnPort` (argv must contain `--cline-hub-daemon` and `--port <port>`). With a `hidepid` /proc mount, other users' PIDs are not even listed.
- Points for Claude: (1) the `CLINE_MCP_CLINE_ENTRY` override on Windows; (2) the PID-reuse window; (3) `pathsNotBeyondLinks` runs on all OSes (S7.x pair written by the supervisor, please review it); (4) proposed flaky F3 in baseline.md.
